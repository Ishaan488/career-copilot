# Architecture Decision Records

Format: Context → Decision → Consequences. Status: Accepted unless stated.

## ADR-001 Modular monolith, two processes
Context: personal machine, limited RAM. Decision: one repo/package, `web` + `worker` processes. Consequence: simple deploy; boundaries enforced by lint (`dependency-cruiser`) so modules can be extracted later.

## ADR-002 Next.js App Router for UI and REST API
Decision: route handlers are thin adapters over module services. Rationale: one framework, no separate API server. Consequence: long jobs MUST NOT run in route handlers; they enqueue.

## ADR-003 Drizzle ORM over Prisma
Rationale: SQL-first, lighter runtime (no engine binary), easy partial unique indexes, JSONB, `FOR UPDATE SKIP LOCKED`, simple migrations. Consequence: write raw `sql` for advanced constraints; migrations generated by drizzle-kit and hand-edited when needed.

## ADR-004 pg-boss for the queue
Rationale: Postgres-backed, retries/backoff/schedules/singleton keys built in, no Redis. Consequence: queue tables live in schema `pgboss` managed by the library. Idempotency via `singletonKey`. `background_jobs` custom table is NOT created.

## ADR-005 Workflow engine = explicit step machine in Postgres (no Temporal)
Rationale: only one long-running workflow type (application) plus simple pipelines. `workflow_checkpoints` stores `step`, `state` JSON, `version`. Each step is idempotent and re-entrant. Consequence: runner is ~200 lines, fully testable.

## ADR-006 Gemini behind `AIProvider`
Decision: interface `generateStructured<T>(task, input, zodSchema)`; Gemini impl uses `responseSchema`/JSON mode; model per task from settings. Consequence: no `@google/genai` import outside `modules/ai/providers/gemini.ts`. Model names are config, verified at M5 against live API docs (do not hardcode from memory).

## ADR-007 Local access protection = passcode + cookie session, bind 127.0.0.1
Rationale: single user; avoids OAuth complexity; protects against other local web pages (CSRF via SameSite=Strict + Origin check). Consequence: if later hosted on VPS, must add HTTPS + reverse proxy (doc 16).

## ADR-008 TypeScript only; no Python
Rationale: all needs (Gemini SDK, Playwright, PDF/DOCX, IMAP) have mature Node libs.

## ADR-009 No LinkedIn/Naukri scraping
Rationale: ToS/anti-bot. Supported via email alerts, URL import, manual paste. Revisit only if user provides an authorized method.

## ADR-010 Rules-as-data policy engine
Rationale: user must change policy without code. Typed rule objects, evaluated by pure interpreter, versioned; each decision persisted with inputs and rule results.

## ADR-011 Submission idempotency via intent row + unique partial index
Decision: `application_submissions` row (`status=intent`) inserted in a transaction BEFORE clicking submit; partial unique index permits only one non-terminal-failed row per application. Post-click uncertainty → `unverified`, never auto-retried. See doc 10 §5.

## ADR-012 Resume PDF via Playwright, DOCX via `docx`
Rationale: no LaTeX toolchain required; LaTeX optional later.

## ADR-013 Outbox for notifications and queue enqueue-after-commit
Decision: notifications written in same transaction as the triggering change; a notification worker delivers. For enqueue, use pg-boss `send` with the same DB connection when transactional, else outbox row + relay.

## ADR-014 Evidence-first model
Decision: `evidence` rows are immutable; assessments reference evidence ids; every claim carries `verification_status` ∈ {verified, partially_verified, ai_estimate, unverified, contradictory, unknown}.
